# 沈清禾戰鬥美術：問題分析、生產範圍與驗收計畫

日期：2026-11-27。對象：巔峰版沈清禾（shen_peak）。本計畫承接擁有者要求：先做一位女生，必須涵蓋普攻、小招、大招；素材與可重現來源直接存入 Git。

## 1. 現況與失敗原因

批次 2 是試作，不是合格的整套動畫。普攻、輕受擊、重受擊與千仞本體沒有通過相鄰輪廓檢查。小招斷流、雲棧飛花、輕身訣沒有製作專屬角色動作。待機、特寫和三組特效僅通過量測，尚不能視為擁有者已接受。

| 問題 | 證據／影響 | 修正方式 |
| --- | --- | --- |
| 範圍漏項 | 上次 9 組試作不含三個小招；「一位女生整套」被縮成了試做子集 | 以 manifest.json 逐組列 5 招及配套，不以總格數報進度 |
| 關鍵姿勢不足 | 普攻約 7 個時點、大招使用少量姿勢並回走同一姿勢；不足以描述伸展、受力與回收 | 先設計每招的完整運動，再畫中間姿勢 |
| 非剛體變形破壞肢體 | 舊 TPS 網格、兩張圖混合與另畫劍刃，出現手臂／軀幹拉扯及接點變形；普攻第 18 格特別明顯 | 舊補間圖不再作新動畫母版；持劍手、手腕、肩肘與劍一起畫，逐格檢查 |
| 動作辨識不足 | 點星應短促前刺；千仞應快速連劍。舊稿常像相似的伸手動作加不同光效 | 三小招及大招各有清楚架式、節奏、兵器軌跡；關掉特效仍能分辨 |
| 節奏單一 | 舊攻擊幾乎均為每格 42ms；能播放卻沒有足夠的起勢、爆發與收勢層次 | 依 24 拍建立時間表，42／83ms 等合理配拍，不以重複幀湊數 |
| 衣髮變化沒有受力依據 | 額外局部擺動不等於與身體運動連貫的二次動作 | 每個過渡重新檢視衣褶、髮流、袖口、垂飾的延遲與回彈 |
| 驗收混淆 | 113 項程式測試只說明程式行為；180 播放格也不等於 180 張完成原畫 | 檔案量測、美術審看、Godot 實播、擁有者接受分欄記錄 |
| 保存節點不足 | 上次實錄未推送即換環境，原錄影無法取回 | 每個階段保存來源、清單與狀態；推送後讀回核對，再進下一段 |

## 3. 五招的美術設計

| 招式 | 人物動作 | 特效／命中 | 必須能辨認的差異 |
| --- | --- | --- | --- |
| 點星／普攻 | 微收劍至身側、重心準備、單次直刺、短餘勢、回收 | 一道細銳劍光，命中快速收束 | 短、準、單次，不畫成大片橫掃 |
| 斷流／小招 | 小幅格開、轉腕帶動前臂、斜向截斬、穩定收勢 | 短而集中的截斷劍光，配截招事件 | 格擋後截斬，不能沿用普攻伸手 |
| 雲棧飛花／小招 | 蓄勢、較大的橫向揮劍、衣袖展開、回收 | 扇形多道薄劍氣，屬遠攻；不把人滑到敵人面前 | 橫掃與遠距擴散 |
| 輕身訣／小招 | 持劍手穩定、自由手運氣、姿態輕提、衣髮上揚 | 氣流繞自己腳與身體，增益生效 | 自身施法；沒有對手受擊或假傷害火花 |
| 雲棧・千仞／大招 | 專屬低重心架勢、上提蓄勢、至少數個清楚不同的連劍姿態、餘勢、回收 | 多束細銳連劍光隨節奏出現，中央命中最亮；先特寫再出招 | 連劍與全身發力，不是普攻放大或倒播姿勢 |

這些是本輪的動作設計選擇，必須用原畫與實播驗證，不把設計文字算成已完成美術。

## 4. 生產方法與順序

1. 固定原設定的臉、身材、紫色服裝、銀色燕形髮簪、紅墜飾、長髮、靴與劍。持劍手沿用原圖，不在動作中換手。先做點星的 6 張不同關鍵原畫與時間表。
2. 原畫先審人體、持劍、剪影與重心；不合格的原畫先改。之後畫中間姿勢，逐段檢查手腕與劍的連接，不再把舊變形幀拿來湊數。
3. 點星先完成一條通過量測與自我審看的動畫，同時建立短程的輕受擊配對。這是製作方法的檢驗，先不量產整套。
4. 斷流 → 雲棧飛花 → 輕身訣：三組專屬本體及各自特效全部列清，不用普攻重命名。
5. 重受擊與蓄招 → 千仞本體 → 專屬特效與特寫 → 其餘 P1／P2 配套。
6. 在隔離的 Godot 測試副本接入；所有五招、受擊配對、增益生效、打斷及循環均試播後，才移交正式接入。

骨骼、網格或程序工具仍可用於輔助，但最終圖片中的關節、手劍接點、遮擋與衣髮必須成立；遇到拓樸或透視改變，應重畫。禁止把「跑得出來」當成「變形品質可收」。

## 5. 四層驗收

### A. 檔案與量測（沿用 tools/anim_spec.json，不降低門檻）

- 角色 512×512 或同比例 1024×1024；本輪優先交連號單格 PNG。腳底為 512 格的 y=480±3，放大同比例換算；非騰空幀不得滑離基準。
- 透明角、無裁切；服裝與兵器均在畫布內，邊緣至少保留現行規格安全距離。陰影與世界移動由遊戲處理。
- 有效不同圖達表列下限；相鄰不得連續重複。單張不超過 125ms，整段時間及循環段時間達標。
- 一般相鄰輪廓變化 ≤25%；真的繪有拖影並列入 smear_frames 的例外 ≤40%，每條動作最多 3 對。不能單純加標籤繞過失敗。
- 攻擊首尾與待機輪廓差 ≤10%；普攻出手前／後有效圖至少 4／6，小招 6／10、大招 10／14。
- 受擊第一或第二張就是最重受力，第一張和待機輪廓差 ≥25%；待機與 ready 身高誤差 ≤2%。
- 命中型特效亮度峰值在命中幀前後一格以內，末幀亮度 ≤峰值15%；循環接點沿用現行量測公式。
- 特寫 2560×720 或同比例更大、同組同尺寸、不透明，至少6張；畫面不烘焙招式文字。
- 新增小招特效 ID 必須同步 data/vfx.json、moves.json 的 fx 與 anim_spec.json 的類別；未接入前標為 planned_config，不能假稱已通過現有 checker。

### B. 逐格與影片美術審看

| 檢查 | 通過條件 | 失敗處理 |
| --- | --- | --- |
| 人體與持劍 | 無多餘／缺失肢體、無非刻意重影、關節彎曲合理、手握劍柄、鋼刃不隨網格彎掉 | 任一重大錯誤，該段退回 |
| 人物一致 | 臉、髮簪、服裝結構、顏色、頭身比與兵器比例一致 | 不能以特效遮住差異 |
| 動作完整 | 起勢、預備、出手、生效、餘勢、收勢都看得懂 | 缺一段就補畫，不只延長停格 |
| 重心與軌跡 | 腳踩實、腰肩帶動手臂；點星的直刺沿連續路徑，其餘劍勢有設計弧線 | 不要求所有招式都畫相同弧線 |
| 衣髮跟隨 | 看得到延遲與回彈，符合發力方向，不是獨立亂擺 | 逐格修衣髮 |
| 招式區分 | 關掉特效仍能辨認普攻、三小招與大招的用途 | 同一姿勢換光色不通過 |
| 特效可讀性 | 不蓋住主要人體及命中位置，類型與強度有層次 | 光太多也屬不通過 |
| 正常與慢速 | 正常連看三次無明顯跳／卡；0.25倍速看無破圖 | 保留失敗格號與對照 |

### C. Godot 實際播放

- FrameSet 正確取得每一組的數量；來源路徑、角色識別、專屬招式覆寫、timings_ms、impact_frame、loop_from 均實際生效。
- 攻擊、特效與對手受擊在同一命中事件對上；停頓與退後由程式處理，不再烘焙重複頓幀或世界滑動。
- 輕身訣作用於自己；雲棧飛花對多目標的顯示合理。這兩項不能只測序章，須有明確試播情境。
- 正反面向、待機銜接、重受擊恢復、特寫進出、蓄招／守勢／倒下循環與被打斷都檢查。
- 留下同一提交的正常速、0.25倍速、無特效版本及實際場景錄影；有缺漏或播放替代動作，直接寫出。
- 程式回歸測試只是功能證據，不能替代 A、B、D。

### D. 擁有者審看與正式交付

A、B、C 通過後狀態為 awaiting_owner_review。擁有者確認後才是 accepted。此處不是要求每一步額外請示：使用者已授權開始執行，製作與自我審看持續進行；尚未回覆的美術最終接受狀態不自動填通過。

## 6. 檔案與狀態

批次：assets/incoming/batch_03/。原畫放 characters/shen_peak/source/{動作}/，合格輸出放 frames/，特效放 vfx/，影片與檢查放 preview/、qa/。每組由 manifest.json 記錄 stage、四層 qa、來源與決策。每完成可審看的小批次即推 Git 並讀回核對；未確認遠端保存前不以「已交付」描述。

狀態依序：not_started → keyposes_in_progress → keyposes_review → inbetweens → self_check → runtime_check → awaiting_owner_review → accepted；不通過可隨時 needs_revision。可以生成候選但不得把候選當完成。只有25組全部 accepted，才叫沈清禾整套完成。
