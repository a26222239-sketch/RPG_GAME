## 1. 現在為什麼看起來生硬

批次 1 交的沈清禾三段動作，用量測工具（第 10.1 節）量出來是這樣：

| 動作 | 交了幾格 | 其中不同的圖 | 問題 |
| --- | --- | --- | --- |
| 待機 | 6 | 4 | 每格停 200 毫秒，等於一秒只換 5 次畫面，看起來一頓一頓的。整張圖只有微微的伸縮，頭髮與衣擺沒有自己的擺動 |
| 出劍 | 6 | 4 | 第 2、3 格是同一張；從預備到出劍只隔一格，人形輪廓一次變了 41%（上限 25%）。出手前只有 2 張、出手後只有 2 張，所以看不到蓄力與揮過去的過程，劍像是瞬間移動到定位 |
| 受擊 | 3 | 2 | 第 1 格還是站姿，挨打後慢一拍才有反應；中間一張受擊姿勢停 155 毫秒，然後一格就跳回站姿，沒有回彈與恢復 |

歸納起來是三件事：

1. **張數太少**。關鍵姿勢之間沒有中間的過渡，眼睛看到的是「換圖」而不是「動作」。
2. **用停留代替動作**。同一張圖重複或停很久，畫面就定住。
3. **只有身體在動**。真實的動作裡，頭髮、衣擺、袖子、髮帶會比身體慢一兩拍才跟上，停下來時還會甩過頭再回來。少了這一層，就算張數夠也會像紙板。

下面每一節的規定，都是針對這三件事。

## 2. 時間的單位

動作以**每秒 24 拍**來排。每一張圖停幾拍：

| 停幾拍 | 毫秒 | 用在 |
| --- | --- | --- |
| 1 拍 | 42 | 快的部分：出手、拖影、命中、受擊的頭幾張、特效 |
| 2 拍 | 83 | 一般的部分：待機、預備、收勢、恢復 |
| 3 拍 | 125 | 最長只能到這裡 |

- **任何一張都不可以停超過 125 毫秒。** 需要停住的地方（例如預備到頂、倒地喘息），要畫成「會動的停頓」：姿勢不變，但呼吸、頭髮、衣角還在微微動，連續 2–4 張。
- **張數指「不同的圖」**。同一張圖用兩次只算一張。想讓某一張停久一點，改 `timings_ms`（第 9 節），不要複製一張。
- 動作的總長度與每張的時間由 GPT 決定，寫在 `meta.json`；沒寫的話，程式把所有張數平均排進第 3 節表裡的預設長度。

## 4. 每一類動作怎麼畫

下面以「建議」的張數舉例，標出每一張屬於哪一段。張數可以增減，只要每一段都有、總數不低於「至少」。所有動作都是**原地**的：衝到對手面前、挨打後退，由程式移動整個人（第 12 節）。

### 4.1 待機 `idle`（16 張，每張 83 毫秒，約 1.3 秒一輪）

- 一次完整的呼吸：吸氣 8 張、吐氣 8 張。胸口與肩膀起伏 4–8 像素（以 512 格計）。
- **頭髮、髮帶、衣擺、袖口要比身體晚 2–3 張才跟著動**，幅度比身體大。這是待機看起來活著的關鍵。
- 兵器隨手微微晃，不要完全靜止。
- 第 16 張要能自然接回第 1 張。第 1 張就是遊戲裡站姿圖的姿勢（`frames/stand.png`），其他動作的第一張與最後一張都要接近它。
- 不可以只把整張圖拉伸、平移或變形來做呼吸。每一張都要重新畫過頭髮與衣服。

### 4.2 準備出手 `ready`（10 張，循環）

- 從待機換成戰鬥架式：重心放低、兵器舉到出手的位置、眼神盯著前方。
- 循環的內容和待機一樣是呼吸與頭髮衣擺的擺動，但幅度小、節奏快一點，帶著蓄勢待發的緊繃。

### 4.3 蓄招 `charge`（14 張：進場 4、循環 10）

- 第 1–4 張：從待機進入運氣的姿勢（兵器收到身側或雙手結印），一拍一張。
- 第 5–14 張循環：內力外放，**衣擺、頭髮被從下往上的氣流掀起**，持續翻動；身體穩住不動。
- `meta.json` 寫 `"loop_from": 5`，程式播完一輪後從第 5 張開始循環。
- 氣流本身的光由特效 `charge_aura` 畫，角色圖裡只畫被氣流吹動的頭髮衣服。

### 4.4 普攻 `attack_light`（16 張，約 0.95 秒）

| 段 | 張 | 每張 | 畫什麼 |
| --- | --- | --- | --- |
| 起手 | 1 | 42 | 待機的第 1 張（或非常接近） |
| 預備 | 2–5 | 83, 83, 42, 42 | **先往反方向收**：重心後移、肩膀轉開、兵器往後拉。這一段讓人看得出「要出手了」 |
| 出手 | 6–8 | 42 | 往前揮出。第 6、7 張可以是拖影（第 5.4 條） |
| 命中 | 9 | 83 | 手臂或兵器完全伸展到對手的位置，這一張就是 `impact_frame` |
| 餘勢 | 10–12 | 42 | 兵器繼續往前或往下劃過去一點，身體被帶動，**頭髮衣擺還在往前甩** |
| 收勢 | 13–16 | 83 | 收回待機。頭髮衣擺甩回來、再晃一下才停。第 16 張接近待機第 1 張 |

`meta.json`：`"attack_light": { "timings_ms": [42, 83, 83, 42, 42, 42, 42, 42, 83, 42, 42, 42, 83, 83, 83, 83], "impact_frame": 9, "smear_frames": [6, 7] }`

### 4.5 小招 `attack_heavy`、`cast`（24 張，約 1.1 秒）

| 段 | 張 | 畫什麼 |
| --- | --- | --- |
| 起手 | 1 | 待機第 1 張 |
| 預備 | 2–7 | 比普攻更大、更慢的預備：可以踏一步、轉腰、兵器舉過頭。**第 6–7 張是預備到頂的「會動的停頓」** |
| 出手 | 8–11 | 一拍一張，其中 2 張拖影 |
| 命中 | 12 | `impact_frame` |
| 餘勢 | 13–16 | 招式的力道帶著身體往前，重心壓低，衣擺大幅甩動 |
| 收勢 | 17–24 | 慢慢站回待機，頭髮衣擺回彈兩次才停 |

施法（`cast`，例如溫蘅的封穴）同樣的分段：預備是運氣、結印或捻針；出手是推掌或彈指送出；命中是手勢完全打開的那一張。

### 4.6 大招 `{招式識別碼}`（40 張，約 1.8 秒）

大招在遊戲裡的順序是：**蓄招（`charge` 循環＋蓄招氣場）→ 特寫（第 6 節，約 1.2 秒）→ 大招動作 → 命中時大招特效最亮、對手做重的受擊、畫面停 0.14 秒**。特寫播完才開始這一段，所以第一張要從待機開始。

| 段 | 張 | 畫什麼 |
| --- | --- | --- |
| 起手 | 1 | 待機第 1 張 |
| 起勢 | 2–9 | 擺出這一招專屬的架勢，內力外放，衣擺頭髮被吹起來。這是大招的「招牌姿勢」，要和普攻、小招明顯不同 |
| 蓄到頂 | 10–13 | 最大的預備姿勢，會動的停頓 |
| 爆發 | 14–19 | 一拍一張，其中 2–3 張拖影。動作幅度是全遊戲最大的 |
| 命中 | 20–21 | 第 20 張是 `impact_frame` |
| 餘勢 | 22–29 | 反作用力帶著身體，兵器或掌勢收不住地繼續；頭髮衣擺大幅甩動 |
| 收勢 | 30–40 | 回到待機。可以帶一點脫力或喘息，第 40 張接近待機第 1 張 |

各人的大招要畫出不同的性格（招式的畫面要求見需求單第 4.3 節）：

- 燕回「萬法歸一」：所有的光匯成一劍，貫穿出去。整個序章最重的一擊。
- 沈清禾「雲棧・千仞」：極快的連劍，爆發段可以用多張連續的拖影表現千道劍光。
- 霍嶽「斷岳」：刀舉過頭，由上往下劈，落點地面迸裂（裂地由特效畫）。
- 溫蘅「回春・遍照」：治療的大招沒有「打中」，命中那一張是雙手展開、光芒最盛的時候。
- 殷九淵「九淵覆世」：雙掌推出，黑紫的氣勁像潮水一樣橫掃。

### 4.7 受擊（輕）`hit`（10 張，每張 42 毫秒，約 0.4 秒）

| 段 | 張 | 畫什麼 |
| --- | --- | --- |
| 挨打 | 1 | **第一張就是最重的那一下**，不要從站姿開始。頭往後甩、肩膀聳起、眼睛瞇緊、上身往後彎，兵器偏離 |
| 回彈 | 2–3 | 身體還在往後，**頭髮與衣擺因為慣性往前（朝攻擊者的方向）甩** |
| 恢復 | 4–10 | 慢慢回正；頭髮衣擺甩回來，晃一下才停。第 10 張接近待機第 1 張 |

### 4.8 受擊（重）`hit_heavy`（18 張，約 0.9 秒）

被小招與大招打中時用。比輕的受擊**誇張得多**：

| 段 | 張 | 畫什麼 |
| --- | --- | --- |
| 挨打 | 1 | 整個上身被打得往後折，手臂甩開，一隻腳離地或往後滑 |
| 被擊退 | 2–6 | 失去平衡，踉蹌退步（原地踏步，整個人往後的位移由程式做 72 像素），頭髮衣擺往前大甩 |
| 穩住 | 7–10 | 壓低重心、兵器拄地或架在身前，硬撐住 |
| 恢復 | 11–18 | 喘一口氣站回待機，第 18 張接近待機第 1 張 |

前 10 張一拍一張，後 8 張兩拍一張。兩隻腳都離地的那幾張，寫進 `airborne_frames`（第 9 節），量測工具就不檢查那幾張的腳底。

### 4.9 守勢 `guard`（12 張：進場 4、循環 8）

- 第 1–4 張：一拍一張，迅速擺出防禦架式（兵器橫在身前、雙臂護住要害）。
- 第 5–12 張循環：架式不變，呼吸與頭髮衣擺微動，兵器有一點受力的顫動。寫 `"loop_from": 5`。
- 守勢的護體光罩由特效 `guard` 畫，人物圖裡不畫。

### 4.10 破綻 `stagger`（12 張，循環）

- 架式被打散、門戶大開：身體往後仰、兵器垂下或手臂張開、腳步不穩，左右晃動。
- 殷九淵的破綻是在序章被沈清禾與霍嶽從背後架住的時候，所以他的破綻要像**被兩人制住、掙扎**：手臂被往後拉、上身挺出、表情驚怒。

### 4.11 倒下 `down`（20 張：倒下 10、喘息循環 10）

- 序章裡倒下的只有殷九淵，而且是**單膝跪地**，不是倒地不起：他跪著還要說好幾句話。
- 第 1–10 張：被最後一擊打中，往後一晃，然後一膝落地、一手撐地或撐膝。
- 第 11–20 張循環：跪著喘息，肩膀起伏，頭髮垂下微動。寫 `"loop_from": 11`。

### 4.12 行走 `walk`（12 張，循環）

- 標準的走路循環：一步 6 張、兩步 12 張。原地踏步，前進的位移由程式做。
- 序章裡只有燕回最後走向殷九淵時用到，步伐要沉、慢。

## 5. 讓動作不生硬的八條畫法

每一個動作都要做到這八條。第 10.2 節的人工審看就是逐條看這些。

1. **預備動作。** 每一次出手之前，身體先往相反方向收。沒有預備的出手，看起來像抽搐。
2. **弧線。** 手、兵器尖端、頭的移動路徑要是圓滑的弧線，不是直線、也不能忽前忽後。把一個動作所有張數疊在一起看，兵器尖端的位置應該排成一條順的曲線。
3. **間距。** 接近關鍵姿勢的地方，相鄰兩張的差距小（慢進慢出）；中段差距大。不要把中間的張數平均分配。
4. **拖影。** 揮得最快的 1–3 張，可以把兵器或手臂拉長、畫成殘影，讓眼睛跟得上。拖影的張數寫進 `smear_frames`，量測工具對這幾張放寬（第 10.1 節）。
5. **跟隨與重疊。** 頭髮、髮帶、衣擺、袖子、配飾，**每一張都要重新畫**：身體動，它們晚 1–3 張才跟上；身體停，它們還會甩過頭再回來。這是最能讓動作活起來的一條。
6. **重心。** 雙腳踩實地，不能飄。踏步、轉身時看得出重心從一隻腳移到另一隻腳。
7. **不要定住。** 任何一張不停超過 125 毫秒；要停的地方畫成會動的停頓。
8. **人物一致。** 臉、身材比例、服裝、配色、兵器長度每一張都一樣，和設定圖一致。沒有多出或少掉的手指與手腳，兵器不會忽長忽短。

## 8. 製作流程

建議分三步交，每一步都先給擁有者看過再往下做，免得整組畫完才發現方向不對。

**第一步：關鍵姿勢（每個動作 3–6 張）**

- 用遊戲裡的站姿圖 `frames/stand.png` 當第一張的底，所有關鍵姿勢都對著它畫，確保人的大小與腳底位置一致。
- 每個動作畫出：起手、預備到頂、命中、餘勢最遠、收勢。受擊畫：挨打最重、回彈、恢復中。
- 附一張**時間表**：每個關鍵姿勢放在第幾張、中間要補幾張、每張停幾拍。
- 交付：關鍵姿勢的圖、時間表、一段只有關鍵姿勢的預覽影片（照時間表的速度播，沒補的地方停住）。

**第二步：中間姿勢與補間**

- 先畫每兩個關鍵姿勢之間的「中間姿勢」，決定弧線與間距（第 5 節第 2、3 條）。
- 再補齊其餘的張數。補間怎麼做由 GPT 決定，例如：
  - 每一張都用產圖工具畫，參考前一張與下一個關鍵姿勢；
  - 在自己的工具裡（Spine、After Effects、Godot、任何能做骨骼或網格變形的軟體）把關鍵姿勢做成會動的版本、輸出中間的張數，**再逐張補畫頭髮、衣擺、拖影**。
- 用骨骼或網格變形做補間是可以的：那是 GPT 自己的製作手段，交來的仍是一張一張的逐格圖。（設計文件不採用骨骼，是因為那樣動作得由 Claude 來做；不是禁止 GPT 使用。）
- 不可以只靠把整張圖拉伸、扭曲、平移來產生中間張數而不重畫頭髮衣服——那正是現在待機看起來僵硬的原因。

**第三步：自我檢查後交付**

1. 在專案根目錄執行 `python3 tools/check_frames.py assets/incoming/batch_02`（換成這一批的資料夾），所有項目都要「通過」。
2. 輸出預覽影片：正常速度一段、0.25 倍速一段，自己照第 10.2 節逐條看。
3. 交付：圖、`meta.json`、預覽影片，放在 `assets/incoming/{批次}/`，路徑照需求單。

## 9. meta.json 的寫法

每個角色的 `frames/` 資料夾一個 `meta.json`，特效的在 `vfx/meta.json`。每個欄位都可以省略。

| 欄位 | 意思 |
| --- | --- |
| `timings_ms` | 每一張停幾毫秒，一張一個數字。數量要和張數相同 |
| `fps` | 每秒幾張，每張一樣久。沒有 `timings_ms` 時才看 |
| `impact_frame` | 命中是第幾張。和 `impact_time` 都寫的話用 `impact_time` |
| `impact_time` | 命中是開始後第幾秒 |
| `smear_frames` | 哪幾張是拖影（量測工具對這幾張放寬，第 10.1 節） |
| `airborne_frames` | 哪幾張雙腳都離地（量測工具不檢查這幾張的腳底） |
| `loop_from` | 循環的動作播完一輪之後，從第幾張開始循環。守勢、倒下寫了這個，就不會停在最後一張不動 |
| `frame_index_base`（寫在最外層） | 張數從幾算起。預設 1；寫 0 表示第一張是 0 |

例子（沈清禾，照這份文件的建議張數）：

```json
{
  "attack_light": {
    "timings_ms": [42, 83, 83, 42, 42, 42, 42, 42, 83, 42, 42, 42, 83, 83, 83, 83],
    "impact_frame": 9,
    "smear_frames": [6, 7]
  },
  "hit": { "timings_ms": [42, 42, 42, 42, 42, 42, 42, 42, 42, 42] },
  "hit_heavy": { "timings_ms": [42, 42, 42, 42, 42, 42, 42, 42, 42, 42, 83, 83, 83, 83, 83, 83, 83, 83] },
  "guard": { "loop_from": 5 },
  "charge": { "loop_from": 5 },
  "shen_qianren": { "fps": 22, "impact_frame": 20, "smear_frames": [15, 16, 17] }
}
```

## 10. 允收標準

一組圖要**兩部分都通過**才算驗收通過。

### 10.1 量得出來的（工具自動檢查）

執行 `python3 tools/check_frames.py`（不加參數是檢查遊戲裡的正式資料夾；加上資料夾路徑是檢查一批交付）。每一項的意思與門檻：

**角色動作**

| 項目 | 通過的條件 |
| --- | --- |
| 格子尺寸 | 每格是正方形，邊長是 512 或 1024（殷九淵 768 或 1536） |
| 真的透明 | 格子的四個角完全透明 |
| 張數 | 不同的圖的張數 ≥ 第 3 節的「至少」 |
| 沒有連續重複 | 相鄰兩張不是同一張圖 |
| 每張停的時間 | 每一張 ≤ 125 毫秒 |
| 總長度 | 在第 3 節的範圍內（有進場的動作只算循環的那一段） |
| 相鄰兩張不跳 | 相鄰兩張的人形輪廓變化 ≤ 25%；拖影那幾張 ≤ 40%，每個動作最多 3 對。循環的動作，最後一張接回循環起點也算一對 |
| 腳底在同一條線上 | 每一張的腳底在離格子底邊 32 像素的線上，誤差 3 像素以內（兩倍大的圖照比例）。`airborne_frames` 列的那幾張不檢查 |
| 沒有超出格子 | 人與兵器沒有碰到格子的上緣或左右兩邊 |
| 人的大小和站姿一致 | 待機與準備出手的每一張，身高和站姿圖相差 2% 以內 |
| 第一張接得上待機 | 普攻、小招、大招的第一張，和待機第一張的輪廓差 ≤ 10% |
| 最後一張回到待機 | 普攻、小招、大招、兩種受擊的最後一張，和待機第一張的輪廓差 ≤ 10% |
| 第一張就是挨打最重的一下 | 兩種受擊：離待機最遠的是第 1 或第 2 張，而且第 1 張和待機的輪廓差 ≥ 25% |
| 標了出手點 | 普攻、小招、大招在 `meta.json` 寫了 `impact_frame` 或 `impact_time` |
| 出手前後的張數 | 出手點之前、之後各有幾張不同的圖：普攻 4 與 6、小招 6 與 10、大招 10 與 14 以上 |

「人形輪廓變化」是把兩張圖不透明的部分疊起來，不重疊的面積佔兩張合起來的比例。0% 是完全一樣，100% 是完全不重疊。批次 1 的出劍與受擊，相鄰兩張是 40–48%。

這些門檻是第一版，是用批次 1 的圖和合成的測試圖定出來的。重新試做沈清禾之後，如果有哪一條在畫得順的動作上也過不了，我會依實際情況調整，改動寫進文件最後的變更紀錄。

## 12. 程式這一邊會做的，圖裡不必畫

| 演出 | 怎麼做 |
| --- | --- |
| 衝到對手面前、打完退回 | 程式移動整個人 |
| 受擊後退 | 輕的受擊退 26 像素、重的退 72 像素，再回到原位；同時整個人閃紅一下 |
| 頓幀 | 命中的瞬間整個畫面幾乎停住：普攻 0.06 秒、小招 0.09 秒、大招 0.14 秒。所以命中那一張不必再額外停留 |
| 畫面震動、閃白 | 大招與劇本指定的地方 |
| 大招特寫的演出 | 暗場、長條滑入滑出、邊線、招式名、推近、敵方翻轉（第 6.1 節） |
| 特效的染色與對位 | 共用特效依招式的勁路染色；對準命中點或腳底 |
| 傷害數字、腳下的影子、頭上的狀態標籤 | 程式畫 |
| 重的受擊還沒交、輕的有 | 先用輕的那一組，退得遠一點 |
| 某個動作還沒交 | 繼續用站姿圖做暫用的動作 |
